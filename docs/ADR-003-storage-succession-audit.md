# ADR 003: Audited metrics, usable storage, controlled succession

Accepted 2026-10-14. Extends [ADR-002](ADR-002-revisions-removal-versioning.md). Engine `0.3.0`, rules `phase-world-3`, evaluator `phase-evaluator-3`.

## Context

An audit of v0.2.0 ([audit/AUDIT-v0.2.0.md](audit/AUDIT-v0.2.0.md)) found four problems:

- Claims contradicted the evidence (512 alloy in all worlds, a "fair" retirement comparison).
- Retiree goods were stranded in storage that could not be withdrawn.
- The world seed could be recovered from controller input.
- Held-out case failures reached agent memories.

## Decisions

1. **An independent reducer.** `genesis/reducer.py` computes every reported metric from export events. It reconstructs holdings and must reconcile with the final state. It imports nothing from the engine. Every accepted action records `energy_charged`, and environment events record per-agent fatigue, so energy can be fully accounted for.
2. **A storage contract.** `deposit` and `withdraw` have membership, reach and stock checks, and every flow is recorded. Capacity is unlimited by declaration. Storage access is independent of knowledge access.
3. **Knowledge access as a capability.** `library` gates inspection, and execution requires holding the artifact. `sharing` sets the initial capability, and `successor_access` sets the successors'.
4. **Lifecycle transition.** Retirement archives identity and history and moves holdings to storage. Fresh successors get new identities and only a typed inheritance package (`library` / `none` / labelled `direct` control).
5. **Controlled succession experiment.** Matched continuations are forked from one committed checkpoint, with the same retirees, the same transfer rule and fresh successors. A physical-parity hash with declared masks checks the match. Invention is frozen in the diagnostic window, and the live continuation runs as a separate experiment.
6. **Observation boundary.** No seed-derived value reaches controllers. The controller seed is an independent scenario value held inside the controller. Agents receive only aggregate test feedback.
7. **Learn before searching.** Researchers inspect an accessible library procedure before searching from scratch, then revise it. This makes cross-generation revisions possible and recordable.
8. **Declared resource scale.** `ore_per_site` (default 240) lets 20-agent worlds avoid depletion openly. A first 20-agent run at the default scale was correctly marked ineligible.
9. **Copy-on-write attempts.** This was a measured optimisation, verified against the full-copy reference by per-tick hash equality. The rules did not change.
10. **Evidence versioning.** v0.2.0 evidence is preserved under `evidence/superseded/v0.2.0/` with a `VERSION.md`. All v0.3.0 evidence is regenerated by one logged script.

## Consequences

The retention claim is now backed by a controlled design with event-level links: creator, retirement, access, learning, execution and measured saving. Earlier retirement results are kept but labelled descriptive. Runs written by v0.2 cannot be continued under v0.3 rules.
